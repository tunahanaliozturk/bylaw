# Privacy

bylaw is a command-line tool, a GitHub Action and a self-hosted GitHub App that run in your environment: your terminal, your Claude Code or Codex session, your GitHub Actions runner, or a server you run. bylaw's authors run no server for it and collect nothing. There is no telemetry.

What leaves your machine or runner, and where it goes:

- **GitHub.** bylaw reads the pull request, its files, the linked issues and their comments through the GitHub API with the token you give it, and writes review comments when you ask it to post.
- **Your work item tracker, if you configure one.** With a `[jira]`, `[azure_boards]` or `[linear]` table in `.bylaw.toml`, bylaw reads the work items a pull request names from that tracker, with the token you put in the environment ([trackers.md](trackers.md)). Their text joins the requirement text below, and the summary comment quotes their criteria unless `quote_trackers = false`.
- **The model provider you choose.** For the model review (the Action, `bylaw review`), the pull request title, the diff with its file paths, the rule files, the decision sections of accepted ADRs and the requirement text go to that provider under your account and its terms: Anthropic, OpenAI, your Amazon Bedrock, Vertex AI, Microsoft Foundry or Azure OpenAI resource, or the local server you name with `--base-url`, where on `localhost` nothing leaves the machine. Claude in Microsoft Foundry also sends usage metadata and content its safety systems flag to Anthropic. [providers.md](providers.md) has the table, with where each one sends the data and which variables it reads. bylaw asks OpenAI and Azure OpenAI not to store the response (`store: false`). With Claude Code or Codex, the host's own model reads them as part of your session.
- **The Action's workflow run, with a compliance profile on.** The evidence file ([compliance.md](compliance.md)) holds the pull request title, every changed path with its status, the findings with their messages and the logins of people who muted or resolved findings. The Action uploads it as an artifact of the run, which anyone who can read the repository's Actions can download, and which expires with the repository's retention setting. The changed paths are more than the summary comment lists, but all of it is visible to anyone who can read the pull request; a requirement's text is never in it.
- **Your repository, with learning on.** With `[learn] enabled = true`, each closed pull request leaves a record on the repository's own `bylaw-outcomes` branch: per finding its fingerprint, category, cited rule, file and outcome, and the logins of whoever muted or resolved it, plus the pull request's author, number and dates. Never code or messages. Anyone who can read the repository can read the branch, and with `report: pages` the report built from it is a web page ([learning.md](learning.md)).
- **Nothing else.** bylaw sends no data to its authors or to any third party.

- **The GitHub App, if you run it.** GitHub sends pull request events to your server, which reads and writes through the API with tokens it mints for itself and sends to the model provider what the Action sends. It keeps no database: its queue and the list of heads it reviewed live in memory and are gone on restart ([ADR 0017](adr/0017-github-app.md)).

Keys and tokens are read from the environment, from a cloud's own credential chain or, for the app, from files you mount, never written to files, logs or comments. A key meant for one provider is never sent to another.

Questions or concerns: open an issue, or for anything sensitive use the private report described in [SECURITY.md](../SECURITY.md).
